“10M 문서용 RAG 파이프라인을 제로 환각으로 설계하세요”

이게 분명히 구글 L5 인터뷰 라운드에서 나온 질문이었다고 합니다. 인터넷 어딘가에서 우연히 보게 됐는데 솔직히 대부분의 전형적인 분산 시스템 질문들보다 훨씬 더 흥미로운 시스템 설계 문제예요

1. 문서 수집 + 정규화  
- 중복 제거, 형식 표준화, 메타데이터 추출, 버전 히스토리 유지  

2. 하이브리드 검색 (BM25 + 임베딩)  
- BM25는 정확한 키워드 매칭을 처리하고 임베딩은 의미적 의미를 포착  
- 대규모에서 의미 검색만으로는 보통 정밀도가 부족함

3. ANN 검색 + 재순위  
- ANN (근사 최근접 이웃)은 수백만 문서에서 상위 후보 청크를 빠르게 끌어냄  
- 그런 다음 재순위 단계가 쿼리와 검색된 청크를 깊이 비교해 관련성을 개선

4. 소스 신뢰도 점수화  
- 모든 검색된 청크는 신선도, 신뢰 수준, 중복, 검색 일관성에 기반해 점수화  
- 낮은 신뢰도의 컨텍스트는 생성에 절대 크게 영향을 주지 말아야 함

5. 제한된 생성  
- 모델은 검색된 컨텍스트만 사용해 답변 가능 (검색된 컨텍스트 밖에서 새로운 것 발명 금지)

6. 인용 기반 응답  
- 모든 주요 주장마다 정확한 청크, 문서 또는 타임스탬프에 링크  

7. 환각 대처 레이어  
- 검색 신뢰도가 임계값 아래로 떨어지면: “충분한 증거를 찾을 수 없음”  

8. 지속적 평가  
- 적대적 쿼리, 검색 재현율 벤치마크, 환각 테스트를 지속적으로 실행  

9. 캐싱 + 메모리 레이어  
- 고빈도 기업 쿼리와 검색 경로 캐싱 (지연 시간과 출력 개선)

10. 모든 곳에서의 관찰 가능성  
- 검색 경로, 청크 순위, 토큰 귀속, 실패 지점 추적  

또한 10M 문서 규모에서는 검색 품질이 프론티어 모델 자체 보다 더 중요합니다.
