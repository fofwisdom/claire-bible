## 1. Goal and Owner Decisions (2026-11-25)

On 2026-11-25, the repository owner approved adding an official **ChatGPT (Codex + ChatGPT Web/Desktop)** `agent_client` following the same two-surface security boundary established by [`CLAUDE_AGENT_CLIENT_DESIGN.md`](CLAUDE_AGENT_CLIENT_DESIGN.md):

1. **Codex app / Codex CLI (`target = "codex"`, `claire-codex` `v0.0.14`)**: Full ingest, isolated extraction, regeneration from stored raw text, and knowledge graph queries via the unified `claire` skill (`$claire ingest`, `$claire regenerate`, `$claire query`) over Option A (`[mcp_servers.claire]` in `~/.codex/config.toml` via `codex mcp add claire --url ...` and `codex mcp login claire`).
2. **ChatGPT Web & Desktop Normal Chat (Developer Mode Custom MCP Connector)**: **Read-only (`readonly` scope)** search and graph traversal only. Users clear `Allow write access` (`쓰기 권한 허용`) on the OAuth 2.1 consent screen (`CL6` / `CD2`), preventing `extract_read` and write calls on the server because web/desktop chat has no isolated extractor subagent.
3. **`AED8` Clarification**: Server-side `host-cli` providers (`AntigravityProvider`, `CodexProvider`) remain permanently retired (`AE8`), while ChatGPT/Codex joins Antigravity and Claude as a supported OAuth 2.1 `agent_client`.

## 2. Two-Surface Architecture & `AED9` 4-Layer Defense

| Surface | Status | MCP Registration | Isolation Control (Layer 1) |
| :--- | :--- | :--- | :--- |
| **Codex app & Codex CLI** | Supported (`[unverified]` live runtime) | `codex mcp add claire --url "https://<server>/mcp"` + `codex mcp login claire` | `agents/claire-extractor.toml` (`sandbox_mode = "read-only"`), `rules/AGENTS.md`, and unified `skills/claire/SKILL.md` (`$claire ingest`, `$claire regenerate`, `$claire query`) |
| **ChatGPT web & desktop normal chat** | Query only (`readonly`) | Settings -> Connectors -> Developer Mode -> OAuth (`https://<server>/mcp`) | User clears `Allow write access` on `/oauth/authorize` (`CD2`); server rejects `extract_read` and writes |

### Why Read-Only on ChatGPT Web/Desktop
ChatGPT web and desktop chat sessions run in a single conversation context without isolated subagents or deterministic pre-tool hooks. Allowing `extract_read` there would expose untrusted third-party source text to the main chat context alongside other user connectors and tools. Enforcing `readonly` on the OAuth 2.1 consent screen preserves `AED9` Layer 1 on the server without relying on prompt compliance.

## 3. Codex Bundle Packaging (`plugins/codex/claire`)

Built deterministically by `scripts/build_agent_marketplace.py` from `agent_clients/clients/codex/client.toml` (`[adapter]`) and shared `agent_clients/common/` templates:

- `.codex-plugin/plugin.json`: Standard Codex plugin manifest (`name = "claire"`, `skills = "./skills/"`, zero embedded `mcpServers` per Option A).

- `skills/claire/SKILL.md`: Unified router skill (`name: claire`) supporting `$claire ingest`, `$claire regenerate`, and `$claire query`.
- `agents/claire-extractor.md` & `agents/claire-extractor.toml`: Codex custom subagent TOML definition generated by `_render_codex_extractor_toml()` with `name = "claire-extractor"`, `sandbox_mode = "read-only"`, and stripped `developer_instructions` from the shared extractor template.
- `rules/AGENTS.md` & `README.md`: Shared 4-layer defense rules and setup instructions.
- Release archives: `claire-codex-v0.0.14.zip` and `claire-codex-v0.0.14.tar.gz` with root prefix `claire/` and `SHA256SUMS`.
