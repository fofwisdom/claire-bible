서버 간 최근 활동 — 표시 형식 프로토타입

네트워크 모드 루트 페이지(/)의 두 번째 부분 "서버 간 최근 활동"의 최종 형식을 정하기 전에, 서로 다른 세 가지 형식을 같은 데이터로 비교하는 화면입니다. 데이터는 모두 모의 데이터(예시 도메인 b.example, c.example, d.example)이며, 상대 시각은 오늘 15:00을 기준으로 계산합니다. 소유자 평가용이며, 구현이 아닙니다.

평가 포인트

  • 장점: 구현이 이미 있고(recentItemHtml), 한 줄에 한 항목이라 읽는 순서가 시간 순서와 같습니다.
  • 위험: 같은 지식 베이스의 활동이 흩어져 반복되고, 종류를 문장 앞머리로만 구분하므로 20건이 차면 훑어보기 어렵습니다.
  • 확인할 점: 상대 시각("3시간 전")을 더하는 것만으로 충분한지, 아니면 구조 변경이 필요한지.

평가 포인트

  • 장점: 오늘 / 어제 / 이전으로 나뉘어 "새 소식이 있는지"를 한눈에 알 수 있고, 종류 칩으로 관심 있는 활동만 남길 수 있습니다.
  • 위험: 최대 20건이라 필터 후 항목이 몇 개 남지 않을 수 있고, 활동이 드문 서버에서는 "이전" 묶음만 보여 날짜 구분의 의미가 줄어듭니다.
  • 확인할 점: 칩의 상태를 주소(쿼리)에 남길지, 그리고 날짜 경계를 방문자의 시간대로 계산해도 되는지.

평가 포인트

  • 장점: 다른 서버의 지식 베이스 하나에 모인 활동(공개, 승인된 기여, 가져온 문서)을 한 카드에서 보므로, 어떤 지식 베이스와 교류가 활발한지 드러납니다.
  • 위험: 묶음 기준이 지식 베이스이므로 기록이 없는 항목(label/url 없음)은 묶을 수 없어 따로 카드가 됩니다. 이를 서버 단위로 묶으면 서버별 활동 수가 되어 "서버 수/서버 목록 비공개" 결정에 가까워지므로 이 시안은 묶지 않습니다.
  • 위험: 지식 유형(현실/허구)은 20건 안에 "새 공유 지식 베이스" 항목이 있을 때만 알 수 있어, 카드마다 표시가 달라집니다.
  • 확인할 점: 카드 수 = 교류한 원격 지식 베이스 수로 읽힐 수 있는데, 이 정도 노출이 괜찮은지.

세 형식이 모두 지키는 개인정보·공개 규칙

  • 연합 서버 목록은 공개하지 않습니다(소유자 결정, KD15): 서버 디렉터리, 서버 소프트웨어, 서버 수를 별도 부분으로 보여 주지 않습니다. 도메인은 항목의 출처로만 나타납니다.
  • 어떤 항목에도 문서나 문서 제목이 없습니다(제안 문서는 개인 지식 베이스에 있음, KD3, KS5).
  • 기여한 계정은 활성 상태이고 공개 프로필과 사용자 이름이 있을 때만 이름이 나타납니다. 그렇지 않으면 이름을 쓰지 않습니다.
  • 차단이 적용된 도메인의 항목은 목록에 없습니다(서버가 거릅니다).
  • 항목은 최대 20건, 최신순입니다. 원격 지식 베이스 기록이 없으면 제목과 링크 없이 출처 도메인만 보여 줍니다.
  • 다른 서버로 가는 링크는 새 탭에서 열고 rel="noopener noreferrer"를 씁니다. 데이터의 모든 값은 HTML로 해석되지 않도록 이스케이프합니다.
