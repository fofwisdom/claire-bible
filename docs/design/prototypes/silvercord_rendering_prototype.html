요약

vSAN ESA(Express Storage Architecture)는 기존의 캐시·용량 계층을 단일 NVMe 스토리지 풀로 통합해 I/O 경로를 단순화합니다. ESXi 8.0 이상의 커널 스택 위에서 로그 구조화 파일 시스템(vSAN LFS)과 객체 단위 압축·암호화를 결합하여 RAID-5/6 환경에서도 일관된 지연 시간을 유지합니다.

적재 본문

1. 단일 계층 NVMe 스토리지 풀과 LFS 쓰기 경로

OSA(Original Storage Architecture)에서는 디스크 그룹마다 읽기/쓰기 캐시 티어를 별도로 구성해야 했으나, vSAN ESA에서는 모든 NVMe 장치가 동일한 스토리지 풀에 참여합니다. 새 쓰기 요청은 먼저 성능 계층의 vSAN LFS 로그 세그먼트에 순차 기록된 뒤 백그라운드에서 용량 계층으로 대칭 병합됩니다.

Note
비로그인 접속자와 로그인 이용자 모두 동일하게 그래프 패널을 꺼내보고(기본 상태 닫힘), 노드를 가리켜 본문 내 엔티티 강조(CSS Custom Highlight)를 확인할 수 있습니다. 비공개 링크공유 문서에서는 Ring 1 + Ring 2 그래프를 보여주되 다른 문서는 열람할 수 없도록 차단합니다.

2. 분산 합의와 RAID-5 소거 코딩 효율

모든 노드는 ESXi 호스트 간 전용 고속 네트워크를 통해 상태 합의를 수행하며, 분산 합의 메타데이터의 직렬화 지연을 줄여 4+1 소거 코딩에서도 미러링과 유사한 쓰기 처리량을 확보합니다.

  • 인라인 압축: 블록이 로그에 기록되기 전에 4KB 단위로 압축되어 네트워크 복제 대역폭을 절감합니다.
  • 스냅샷 체인 제거: B-Tree 메타데이터 참조를 활용해 다수의 스냅샷에서도 성능 저하를 억제합니다.

3. 운영 전환 시 점검 항목

기존 클러스터에서 이전할 때는 호환 NVMe HCL 목록, 최소 25GbE 이상 네트워크 대역폭, 그리고 vSAN ESA 전용 스토리지 정책 적용 여부를 사전 검증해야 합니다.
