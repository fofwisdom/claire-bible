## 2. git에 없는 로컬 파일 (직접 옮겨야 함)

`.gitignore` 대상이라 푸시로 옮겨지지 않는다. 아래 파일은 모두 원래 컴퓨터의 `~/claire-bible-handoff-2026-11-18.tar.gz`(약 6.4 MB, 권한 0600, 비밀값 포함)에 묶었다. 이 파일을 USB 등 사설 경로로 옮겨 새 컴퓨터의 홈 폴더(`~`)에 둔다. 압축 안의 경로는 저장소 루트 기준이다. 홈 폴더에서 바로 풀면 안 된다.

먼저 새 클론의 저장소 루트로 이동한다(경로는 새 컴퓨터에 맞게 바꾼다).

```bash
cd ~/projects/claire-bible
```

`docker-compose.dev.yml`이 이미 한 번 실행되었다면 Docker가 `.dev/data`를 root 소유로 만들었으므로 압축 해제가 `Permission denied`로 실패한다. 이때는 개발 컨테이너를 멈추고 그 폴더를 옆으로 옮긴 뒤 푼다.

```bash
sudo mv .dev .dev.created-by-docker
```

저장소 파일을 푼다(`claude-memory/`는 제외).

```bash
tar -xzf ~/claire-bible-handoff-2026-11-18.tar.gz --exclude='claude-memory*'
```

Claude 메모리를 이 저장소 경로의 프로젝트 폴더에 푼다(저장소 루트에서 실행).

```bash
M=~/.claude/projects/$(pwd | sed 's#[^A-Za-z0-9]#-#g')/memory && mkdir -p "$M" && tar -xzf ~/claire-bible-handoff-2026-11-18.tar.gz -C "$M" --strip-components=1 claude-memory
```

홈 폴더에서 잘못 풀었다면 홈 폴더에서 아래 두 명령으로 압축에 든 파일만 지운다. 첫 명령은 압축에 든 파일을 지우고, 둘째 명령은 비게 된 폴더만 지운다(원래 있던 `~/.claude` 같은 폴더는 비지 않으므로 남는다). 홈 폴더에 원래 `~/.env`나 `~/.claude/settings.local.json`이 있었다면 압축 해제 때 이미 덮어써졌으므로 따로 복구해야 한다.

```bash
cd ~ && tar -tzf claire-bible-handoff-2026-11-18.tar.gz | grep -v '/$' | while IFS= read -r f; do rm -f -- "$f"; done
```

```bash
cd ~ && tar -tzf claire-bible-handoff-2026-11-18.tar.gz | sed 's#/$##' | awk -F/ '{p=$1; print p; for(i=2;i<=NF;i++){p=p"/"$i; print p}}' | sort -ru | while IFS= read -r d; do rmdir -- "$d" 2>/dev/null; done
```

압축에는 위 표 외에 `.agents/`, `.agent-work/`, `.cb-manuscript/`, `.gemini/`, `.claude/launch.json`, `.claude/settings.local.json`, `scratch/`도 들어 있다. `dist/`, `.venv/`, 캐시, `test-results/`는 넣지 않았다. 묶을 때 서버는 꺼져 있었고 SQLite WAL 파일은 없었다.

| 경로 | 내용 |
|---|---|
| `.env`, `.env.dev` | 로컬 환경 변수, 비밀값 |
| `.dev/data/` (약 1.6 MB) | 개발 DB `claire.db`와 백업 `claire.db.before-v28`. admin이 `setup_required` 상태였다 |
| `data/` (약 27 MB) | 로컬 서버 데이터, 로그, `providers.json` 등 |
| `private/gemini-decisions-api-review.md` | Gemini Decisions API 검토 메모(`docs/ideas/`의 관련 아이디어와 짝) |
| `certs/nsa-r1.crt` | 로컬 인증서 |
| `plugins/fetchers/test_custom.py` | 로컬 시험용 fetcher (`plugins/`는 무시 대상) |
| `~/.claude/projects/-home-fow-projects-claire-bible/memory/` | Claude 에이전트 메모리(작업 규칙, 진행 상태). 저장소 밖에 있다 |

`.venv`, `node_modules`, `test-results/`, `scratch/`는 옮기지 않고 새로 만든다.

## 3. 새 컴퓨터에서 시작

```bash
git clone https://github.com/fofwisdom/claire-bible.git
```

```bash
uv sync --extra dev --extra stealth --extra audio --extra ko
```

`--extra dev`가 없으면 pytest가 설치되지 않는다. 나머지 extra는 `scripts/ci.sh`와 컨테이너 이미지에 맞춘 것이다. E2E 도구는 `e2e/`에서 `npm ci`로 설치한다.

단위 시험:

```bash
PYTHONPATH=$PWD/src .venv/bin/python -m pytest -n 4 -p no:cacheprovider --basetemp=/tmp/ckb tests
```

시험 뒤 `/tmp/ckb`, `/tmp/pytest-of-*`를 지운다(`/tmp`는 작은 tmpfs). Playwright E2E는 `scripts/e2e.sh`로만 실행한다(전체 약 6.5분, 8분을 넘으면 결함).
